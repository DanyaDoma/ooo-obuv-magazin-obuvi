| Д | Клиент: товары без фильтров | Роль `client` | Фильтры и сортировка отсутствуют |
| Д | Менеджер: фильтры и просмотр заказов | Роль `manager` | Фильтры работают, заказы открываются только для чтения |

## 4. Роли и доступ

| Возможность | Гость | Клиент | Менеджер | Администратор |
|---|---:|---:|---:|---:|
| Вход | — | ✓ | ✓ | ✓ |
| Просмотр товаров | ✓ | ✓ | ✓ | ✓ |
| Фильтр, сортировка, поиск товаров | — | — | ✓ | ✓ |
| CRUD товаров | — | — | — | ✓ |
| Просмотр заказов | — | — | ✓ | ✓ |
| CRUD заказов | — | — | — | ✓ |
| Вкладка «Пользователи», поиск и фильтры | — | ✓ | ✓ | ✓ |

Решения по спорным местам:

1. **Главный экран — пользователи.** Задания 2 и 4 называют таблицу с ФИО, логином, ролью и отделом главным экраном. После входа её видят клиент, менеджер и администратор. Гость сразу попадает на вкладку «Товары».
2. **Права проверяются в одном месте.** Класс `RolePermissions` определяет, какие вкладки, панели и кнопки создаются в окне. Скрытые элементы не участвуют в работе.
3. **Клиент не видит заказы.** По предметной области ему доступен только каталог. Отдельного сценария «Мои заказы» в задании нет.
4. **Мягкое удаление товара.** Товар из заказа нельзя удалить физически без потери истории, поэтому `DELETE` переводит `is_active = 0`.

## 6. Технические решения

| Решение | Обоснование |
|---|---|
| C# / .NET 10 / WPF | Соответствует требованию выполнить работу на C#; классическое настольное приложение |
| MySQL 8.0 + MySqlConnector | Прозрачные SQL-запросы, контроль индексов, параметризация |
| Три проекта: Core, App, Tests | Логика отделена от интерфейса, сервисы покрываются тестами |
| bcrypt cost 12 | Пароли из Excel короткие, хранение открытого текста недопустимо |
| Параметризованные запросы | Защита от SQL-инъекций во всех выборках и изменениях |
| Белый список сортировки | Направление и поле сортировки не подставляются из пользовательского ввода |
| Мягкое удаление товаров | Сохраняет ссылочную целостность `order_items` |
| Заказы не меняют `stock_qty` | В исходных данных остаток — независимый атрибут, заказы исторические |
| Один короткий расчёт в транзакции | Создание и изменение заказа целиком либо применяются, либо откатываются |
| Без сессий и токенов | Настольному приложению достаточно проверки пароля при входе; лишняя таблица не нужна |

## 8. Ограничения

| Ограничение | Влияние | Решение |
|---|---|---|
| Нет изображений товаров | Фото не отображаются | Поле в базе остаётся пустым, в задании фото не требуется |
| Дубли ФИО | Неоднозначная привязка заказа | Приоритет роли «клиент», зафиксировано в отчёте импорта |
| Автотестов интерфейса нет | WPF проверялся вручную | Сценарии по ролям описаны в `docs/04-test-report.md` |
| Пароль MySQL зависит от стенда | Ошибка подключения | Строка подключения вынесена в `appsettings.json` |
